## Label ownership

`SceneLabels.tsx` provides a per-Canvas label registry bridged through Fiber's existing React context support. `SceneLabel` registers only DOM content in an effect and a Three group at the requested position. `LabelLayer` renders that content in the application's existing ReactDOM tree. Removing labels or unmounting the Canvas therefore uses ordinary React child cleanup rather than synchronously unmounting a different renderer's root.

Positions are projected from each group's world transform each frame without per-frame React state. Centering, full-viewport FPS output, existing classes/content, pointer-event behavior and depth-derived z-index ranges are retained. Labels behind the camera or outside its near/far planes are hidden. The overlay clips to the Canvas bounds. UI panels and safety alerts keep their existing stacking.

Replaced tags: equipment names/affordance hints, blocked-drop hints, placement previews, pour readouts, heating tags and the development FPS display. Physics, camera behavior, calculations, state stores, particle model and guided workflow were not changed.

The effects demo again has eight projected title/volume labels using this layer. Its eight plain DOM readouts remain as accessible, persistent observations; neither the data nor effect controls changed. A drei upgrade is unnecessary because no application label uses its nested-root Html implementation now.
