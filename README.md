# STEM Virtual Lab

STEM Virtual Lab is an **independent educational platform prototype** designed for STEM students at the Faculty of Education, Assiut University. Its intended direction includes laboratory safety, an academic experiment catalog, virtual laboratory workspaces, guided demonstrations, and eventually AI-assisted explanations.

**Current scope: Tasks A–F immersive virtual laboratory — viewport-filling 3D workbench, mouse-first 3D equipment handles, direct spatial gestures, camera-aware procedural apparatus, proximity-aware contextual guidance, typed event-driven experiment validation, conserved scientific quantities and deterministic retry.** Official curriculum, experiments, safety protocols, and academic content have not been finalized. No university branding or approval is implied.

## Stack

- React 19 and TypeScript 5.9 (strict mode)
- Vite 8 and `@vitejs/plugin-react`
- Tailwind CSS v4 with `@tailwindcss/vite` and CSS-first `@theme` tokens
- React Router (Declarative Mode with `BrowserRouter`)
- Lucide React icons
- Three.js, React Three Fiber v9, Drei, Zustand and Rapier v2 (fixed bench and kinematic equipment colliders)
- ESLint (flat config), typescript-eslint, React Hooks rules and Prettier

TypeScript 5.9 is intentionally used because the current `typescript-eslint` release does not yet support TypeScript 7.

### T05: 3D rendering and interactions

- The 3D scene lives under `src/features/simulations/three/`, separate from the guide, inventory and chemistry data. It uses `LaboratoryScene`, `LaboratoryEnvironment`, `LaboratoryWorkbench`, `LaboratoryLighting`, `LaboratoryCamera`, `SceneInteractionManager`, `EquipmentRenderer`, and six `models/` mesh components. `ModelLoader` supports future local GLB/glTF assets; currently all six apparatus models are fully procedural 3D geometry (glass, liquid volumes, metal/plastic, labeled jars and instrument details). There are **no external 3D asset requests**.
- Geometry uses a **right-handed, metre-scaled world, Y up**, with the workbench surface at Y=0.78. Models use a grounded local pivot at y=0. The registry in `three/sceneConfig.ts` defines equipment identifiers, default positions and collision footprints; drawing code never owns the experiment rules.
- `LaboratoryCanvas` lazy-loads the WebGL 3D canvas with error/unavailable fallback. Orbit camera supports damped rotation, pan and scroll/pinch zoom, with distance, angle and target limits; Reset camera restores the default view. Antialiasing, device-pixel-ratio caps and directional shadows balance quality/performance.
- Vite 8 uses Rolldown vendor groups to split the lazy scene code, React Three components and Three.js engine into separately cacheable chunks. The Three.js engine is relatively large even after splitting; performance should be evaluated on target student devices before deployment.
- `state/useLabSceneStore.ts` stores selected object, active drag, camera reset token and per-object X/Z positions. Inventory and 3D objects share selection. Pointer dragging moves equipment across a bounded tabletop plane; pure movement constraints reject footprint overlaps. Four accessible movement buttons provide an alternative to pointer dragging, and Reset equipment restores initial positions.
- **T05 historical scope:** equipment originally used analytical footprint constraints without active Rapier bodies; T06 adds fixed workbench and kinematic equipment colliders while retaining the same predictable coordinate constraints.
- `tests/sceneState.test.mjs` verifies the registry maps the six catalog items, movement/tabletop bounds, overlap prevention, selection, reset and camera-reset state; route checks confirm that planned and invalid IDs cannot enter the 3D lab.

### T06: Equipment selection, placing and returning

- The bench starts with a beaker and digital balance already present. Other inventory entries are intentionally **not yet on the bench**. Each inventory item has a selection action, a visible **Place** action when unplaced, and separate scientific descriptions. Selected objects can be rotated or returned to inventory. Inventory and Three.js share a Zustand selection ID.
- The **Place** workflow begins with a visible procedural-model preview at a suggested free position. The preview follows an actual perspective-camera **ray** intersecting the plane Y=`BENCH_TOP` in world metres. It becomes teal for valid placements and red with explanatory text for out-of-bounds/overlapping positions. Click the bench or **Confirm placement** to commit; **Cancel** or Escape abandons the preview. Four movement controls permit placement without precise pointer input.
- `three/movement.ts` contains pure placement validation, radius-based tabletop clearance, deterministic suggested positions and error descriptions. Only _currently placed_ items count as collisions. Invalid moves are rejected rather than pushing other equipment or silently clipping through it. Pointer dragging and the movement buttons use the same constraint checks.
- `state/useLabSceneStore.ts` owns item placement/return, preview, dragging, hovering, rotation, equipment resets and feedback. Three.js model geometry does not decide academic validity or simulation progress. Reset equipment restores the original two bench objects; Reset camera is independent.
- `three/LaboratoryPhysics.tsx` activates Rapier with a fixed tabletop collider and explicit **kinematic-position** colliders for placed items. The store remains the authoritative source of valid X/Z positions; the physics world mirrors those transforms for stable non-bouncing contact. Kinematic bodies are **not** automatically separated by Rapier, so the pure footprint checks remain required. There is no free-falling gravity, tilting, or physical liquid behavior yet.
- The 3D canvas disables browser touch scrolling during pointer manipulation; OrbitControls are disabled while moving or placing equipment to avoid conflicts. Hover, selection rings, live placement notices, return/reset actions and alternate movement/rotation buttons provide interaction feedback and keyboard operability.
- `tests/sceneState.test.mjs` now covers preview validity, conflicting placement rejection, confirmation, cancellation, deselection, hover, rotation, returning to inventory and restoring the bench. Full WebGL/camera/physics pointer workflows still require manual testing in a real browser with graphics acceleration.

### T07: Pouring, material addition, stirring and deterministic measurements

- `engine/types.ts` defines explicitly typed commands and effects. `engine/saltExperiment.ts` contains pure action prerequisites, supported actors/targets (`DEMO_ACTION_RULES`), transition validation, conservation of water volume and NaCl mass, capacity checks, simplified dissolution and success criteria.
- `state/useSaltSimulationStore.ts` stores **chemistry state independently from T06 equipment placement** and serializes visually animated operations. Animations are not used to generate measurements; quantities are determined by validated transitions and visual representations follow state updates. Invalid commands return feedback without mutating quantities. `Restart experiment` resets the chemistry and the bench, while `Reset guide` still only resets reading position.
- `components/ExperimentInteractionPanel.tsx` provides explicit source/destination controls, 25/50/100 mL water transfer choices, 1/2/5/10 g salt additions, and stirring actions. Pouring requires both containers on the bench; salt addition requires the beaker, jar, digital balance and water; stirring requires a placed stirring rod, beaker and undissolved salt. Readouts in `SimulationMeasurements.tsx` come directly from the simulation state.
- Starting demonstration quantities: **400 mL water** in a 500 mL container and **100 g NaCl** in the jar. The graduated cylinder holds **100 mL**, the beaker **250 mL**. Containers cannot receive more than capacity, quantities cannot become negative, and unplaced items cannot take part in active commands.
- Demonstration solubility assumption: approximate room-temperature NaCl solubility **35.9 g / 100 mL water** (approximately 20°C), with an **invented teaching rate of at most 4 g newly dissolved per stirring action**. This rate is deliberately _not_ a scientifically calibrated prediction; the objective is to illustrate mass conservation and that dissolution is not formation of a new chemical substance. Stirring stops when no undissolved salt remains or no more salt can dissolve in the current water volume. Adding more water can increase the approximate dissolved amount after additional stirring.
- `three/effects/LiquidFill.tsx` uses actual volume/capacity data to animate cylindrical fill bodies and menisci inside the existing vessel geometry. `three/effects/LaboratoryEffects.tsx` provides lightweight deterministic pour streams, salt granules, stirring ripples and temporary illustrative particles. `three/SimulationSceneEffects.tsx` controls these visuals using the transient effect state; `three/EquipmentRenderer.tsx` links vessel quantities and controlled temporary tilts to their models. No CFD, randomized measurements, new substance production or true fluid dynamics are claimed.
- `tests/saltSimulation.test.mjs` verifies water/salt conservation, source/destination guards, overflow rejection, negative/noninteger quantities, mass transfer, dissolution progress, the solubility limit, re-stirring after adding water and Zustand integration. Browser WebGL animation, touch behavior and frame-rate profiling still require manual device testing.

### T08: Reusable experiment execution and validation

- `engine/workflowTypes.ts` defines a rendering-independent `ExperimentWorkflowDefinition`, five-stage and ordered-step metadata, typed `WorkflowAction` commands, configurable legal actions, structured condition predicates and feedback (`WorkflowValidation`: `valid`, `code`, `severity`, `message`, `stepId`). No React, Three.js or WebGL types are referenced.
- `data/saltExperimentDefinition.ts` contains the **first configuration**: experiment identity/version, required inventory/materials, initial simulated conditions, target measurements, instructor-oriented precautions, step-specific permitted commands, predicate-based validation, completion requirements and the correct physical-dissolution explanation. To add another experiment, supply a definition and a chemistry engine adapter rather than hardcoding new procedural logic inside a React component.
- `engine/workflow.ts` implements a **pure, deterministic** reducer for nine ordered steps: (1) acknowledge safety and prepare; (2) verify beaker placement; (3) fill and record 100 mL in a graduated cylinder; (4) transfer exactly 100 mL to the beaker; (5) select and record 5 g NaCl; (6) add exactly that 5 g to the beaker; (7) stir until no visible solid remains; (8) record the supported observation; (9) review the 100 mL/5 g state and validate completion.
- **Validation is evidence-based:** `validate-step` checks current placements, true container contents, recorded values and previously accepted commands. It cannot advance just because a student clicked Next or an animation ended. The engine re-executes proposed chemistry transitions against an immutable checkpoint and compares actual before/after states, blocking fabricated outcomes or replayed changes. Partial stirring is allowed, but stage completion requires the modelled solid to disappear.
- `state/useSaltSimulationStore.ts` commits accepted T07 chemistry and T08 workflow transitions **atomically**. Wrong order, wrong targets, wrong quantities, repeat attempts, missing instruments and active drag/animation conflicts return structured feedback without changing chemistry or progress. The original five-stage scientific text remains an optional reference; T09 replaced its independent reading-progress UI with an execution-driven guide.
- `state/sessionSelectors.ts` derives a complete cross-store snapshot of active experiment, procedural step and stage, equipment IDs and transforms, selected object, placement/drag/animation status, container water, NaCl mass, recorded quantities, safety notices, validation and completion. Transient pointer positions remain in `useLabSceneStore` so React chemistry panels do not rerender for each pointer movement.
- `components/ExperimentExecutionPanel.tsx` renders a nine-step progress checklist, context-specific action/validation controls, safety notes, recorded measurement status, educational error feedback and the result explanation. `SimulationMeasurements.tsx` differentiates a dissolution objective from **validated procedure completion**; the 3D completion ring now uses the procedural completion flag only.
- `tests/workflowEngine.test.mjs` exercises definition integrity, safety acknowledgment, missing equipment, unsupported/out-of-sequence commands, wrong source/target/ranges, water and salt recording, partial dissolution, final observation, duplicate actions, successful completion and full Zustand/scene integration. Existing T03–T07 tests continue to run.
- **Scientific limitations:** The 100 mL water reading is derived from a simulated cylinder state; the 5 g sodium chloride amount is explicitly **selected** rather than weighed by calibrated hardware. The inherited T07 4 g-per-stir rule is illustrative, not validated kinetics. NaCl dissolution is not a new-compound chemical reaction, and the 3D effects remain non-CFD visualizations. Safety warnings are introductory and do not replace institutional SOPs.

- `components/ExperimentGuide.tsx` is now **authoritative-workflow-driven**: it renders the current T08 procedural step and stage, required apparatus with bench-present indicators, current and recorded values, structured validation feedback, actionable next instructions, and a locked/validated nine-step checklist. It does **not** provide Next buttons that can skip validation. The original five-topic instructional content remains accessible in nested, expandable reference sections without affecting scientific progress.
- `lib/executionGuideSelectors.ts` derives step-specific equipment needs and next instructions from each typed workflow definition's allowed commands, placement predicates, measurements, and accepted command evidence. It does not read React components or Three.js meshes. `components/ExperimentControls.tsx` now shows verified progress from 0/9 to 9/9 (0–100%), not fictitious reading completion.
- `components/ExperimentResults.tsx` mounts **only when `workflow.completed` is true**. It shows the actually recorded water volume and selected salt mass, current beaker contents, modelled dissolved mass, a distinct _simulated observation_, the scientific principle (NaCl disperses as existing ions; no new compound), and an explicit warning that the stirring rate/solubility/selected mass are educational assumptions rather than calibrated laboratory measurements. **Retry experiment** is available directly on the completed result.
- `state/sessionActions.ts` provides one shared **`restartExperimentSession()`** for the workspace header, canvas controls, operations and results. It clears chemistry, workflow, validation messages, recorded measurements, active effects, equipment placement/selection/hover/drag and transforms, then restores the default camera. `useSaltSimulationStore.resetRevision` remounts only the small operations UI to restore default form selections, leaving the heavy WebGL canvas mounted. Timed effect cleanup is attached to the operation component's effect lifecycle; stale `stopEffect` requests cannot restart cleared animations.
- 3D resilience improvements: the scene lazily loads, caps DPR at **1.5**, reuses fixed renderer options, monitors WebGL context loss/restoration with removable event listeners and manual **Retry 3D view** fallback, and bounds camera pan without a recursive controls-update loop. GLB loader memoizes scene clones and isolates optional model asset errors. Transient visual effects only mount their frame updater while active, with progress updates throttled to approximately 24Hz; static fills stop applying transform writes when settled. Geometry is procedural, requiring no licensed third-party asset downloads or attribution in this demo.
- `tests/experimentExperience.test.mjs` verifies guide context changes, missing equipment notices, partial/stirred state advice, complete reset including camera, data, feedback, selections and preview, and cancellation of in-flight effects. The route SSR test checks the initial guide as well as the **conditional** completed results panel. Existing T03–T08 scientific and integration tests remain in the suite.
- **Operational limits:** Browser-delivered 3D WebGL scene/OrbitControls/pointer/touch interactions and frame-rate on target student laptops require independent **real-browser GPU QA**; a clean TypeScript/test/build result does not prove WebGL interaction acceptance. The large Three/Rapier vendor bundle is still a performance concern. The app does not store session progress across full page reloads and has no backend, AI API, Supabase or remote data. Vercel SPA deep-link routing is retained in `vercel.json`.

Those buttons are intentionally no longer mounted in the active laboratory; follow the direct-mouse-gesture walkthrough below instead. The same science predicates and no-skipping guarantees remain.

### Post-T09: Immersive laboratory and direct-manipulation gestures

The active salt route and legacy preview route now use an immersive, full-viewport experience. The main application sidebar, header, page padding and footer are not rendered on those two routes; all other routes retain the original responsive shell. A persistent, lazy-loaded 3D canvas fills the work area; inventory and reference guide are independently collapsible overlays, the next physical action and modelled measurements appear in compact HUDs, results appear only after validated completion, and the utility toolbar contains help, reset, camera reset, fullscreen and exit.

**Direct manipulations:**

- Drag a tool or reagent from the collapsible HTML inventory directly to the 3D workbench; placement uses a camera-ray/table-plane intersection and verifies tabletop bounds and registered footprints. Clicking an item and then choosing a place on the bench remains a fallback.
- Left-drag a placed tool to grab/reposition it, with a stable grab offset, a controlled tabletop plane, valid/invalid ring preview, drag/camera exclusion and pointer capture. Dragging empty space orbits; right-drag empty space pans; wheel zooms. Cancel/loss of capture/focus/visibility terminates a gesture and restores camera control.
- Move the water container beside the graduated cylinder, or the cylinder beside the beaker, then **right-drag downward on the source** (or **Shift + left-drag downward**) to tilt. This mouse gesture must remain held and aligned: the stream starts when the angle crosses 0.45 radians, and **real domain water volume** moves in small whole-mL ticks at up to a deterministic **45 mL/s**. Straightening, leaving the valid target range, releasing, cancelling, an empty source or a full/step-target receiver stops the stream. Source and receiver levels follow actual model state; the visual stream only exists during an active transfer. A fixed 100 mL click/animation no longer triggers water pouring.
- Add the procedural **Spatula** and **Weighing Boat** from inventory. Dip the spatula into the NaCl jar and move it meaningfully to scoop a modelled 5 g portion, then move the loaded spatula beside the boat and release to deposit the actual mass. Move the loaded boat onto the digital balance. The balance displays the **modelled net NaCl mass** from state only while the boat is attached to its pan, marked _SIMULATED · TARED_; an empty/no-boat reading is not fabricated. Move the weighed boat beside the beaker and Shift-drag down to empty its actual solids. The old jar-to-beaker shortcut is not permitted by the active validated experiment.
- Move the stirring rod tip inside the beaker and make repeated **circular mouse paths**, with enough angular travel, path distance and time to reject stationary pointer events or simple back-and-forth shakes. Each accepted stirring cycle applies the documented ≤4 g-per-action **illustrative** dissolution transition; repeat until no modelled undissolved solid remains.
- After each accepted gesture, `state/directInteractions.ts` routes through the existing atomic scientific reducer and workflow predicate validator. Spatial predicates and actor/target/gesture rules reside in `engine/spatialInteractions.ts`; 3D proximity detection resides in `three/equipmentGestures.ts`. `useLabSceneStore.relationships` records validated semantic contacts and clears them upon movement, removal and restart. Invalid/out-of-order/too-weak/wrong-target gestures do not mutate chemistry.
- Evidence-based procedural validation advances automatically once the authoritative chemistry, placement, and recording requirements are satisfied. Safety acknowledgement remains explicit. The active route no longer exposes the old `ExperimentInteractionPanel`/step-validation buttons, although those legacy components remain in the source for history/tests. The optional five-topic reference guide remains accessible without independently advancing execution.

**Manual Task B acceptance sequence:** Open `/experiments/exp-salt-water-001/lab`, acknowledge safety, open inventory and drag cylinder/water/spatula/boat/jar/rod onto bench. Bring water beside cylinder; right-drag down and hold until the graduated cylinder's readable markings reach **100 mL**; release to stop. Move cylinder beside beaker, tilt and hold until the beaker contains **100 mL**. Insert the spatula into the jar and scoop, then release above the weighing boat. Place loaded boat beside/onto the balance and verify **5.0g SIMULATED · TARED** display (no boat displays `--`). Bring the boat near the beaker and tilt to release **5 g**. Move stirring rod tip through circles within the beaker opening; repeat until the modelled undissolved solid is zero. Inspect recorded results, then restart and verify that all apparatus, water, solid quantities, HUD and camera reset. Test releases outside canvas, focus loss, malformed shortcuts, moving out of alignment, overfilling, stationary rod and invalid equipment targets as separate negative cases.

**Limits:** Apparatus bases remain constrained to the bench plane; this is not arbitrary free-flight 6-DOF manipulation, calibrated real weighing, fully mechanical collision-backed mesh stacking, continuous particle-based fluid simulation or measured kinetic chemistry. The spatula's 5 g portion and 45 mL/s flow are explicit **educational model assumptions**, while simulated net mass/volume are faithfully derived from actual domain state. Balance attachment is a semantic 3D relationship with a visual snapped dish; the collider still uses a safe nearby tabletop slot. The browser GPU/pointer behavior, precise alignment feel and device performance still require hands-on verification; TS/unit/SSR/build cannot prove visual quality. Large 3D vendor bundles remain a concern.

`tests/directInteractions.test.mjs` and `tests/physicalActions.test.mjs` cover semantic target/proximity rejection, a full physically triggered **domain** sequence across nine validated steps, interrupted/resumed real-time pour, volume conservation, restart during active flow, invalid scoops and prevention of recording an empty weighing boat. These tests cannot replace browser GPU pointer acceptance.

### Task D: Event-driven procedure validation

The live experiment route no longer advances any procedural step when a visual animation finishes or because a UI procedure button was clicked. `engine/simulationEvents.ts` exposes the **typed** `SimulationEvent` union and a rendering-independent, pure `applySimulationEvent(def, workflow, chemistry, placedIds, event)` reducer. The state adapter `useSaltSimulationStore.emit(event)` records only **accepted events**. Each event includes relevant apparatus IDs and, for physical transfers or stirring, a numeric quantity with an explicit unit (`mL` or `g`).

Accepted semantic events include `SAFETY_ACKNOWLEDGED`, `EQUIPMENT_PLACEMENT_VALIDATED`, `LIQUID_TRANSFER_COMPLETED`, `SOLID_TRANSFER_COMPLETED`, `MASS_MEASUREMENT_RECORDED`, `STIRRING_REQUIREMENT_COMPLETED`, `OBSERVATION_RECORDED`, and `REVIEW_INSPECTED`. Distinct, state-backed scoop and spatula-to-boat deposits are acknowledged without advancing the weighing step until the loaded boat has actually been placed on the balance.

**Evidence pipeline:** A genuine 3D gesture sends a typed scientific command into the pure `saltExperiment.ts` reducer; this state transition is accepted by the existing `workflow.ts` validator and committed atomically. When the exact semantic completion condition becomes true, the store publishes the typed event. The event reducer checks the authoritative chemistry checkpoint, inventory placement, quantity and units, allowed source/target, accepted command counts, conservation, scientific prerequisites, procedural sequence, and duplicate event receipts. It invokes the existing step predicate checks internally to advance only on accepted semantic evidence, never on animation completion. Invalid or forged events **cannot change scientific quantities or procedural progress**. An accepted event is appended to the in-memory `events` log and appears in the measurement HUD; the unified restart clears all events, flags, measurements, equipment state, and active effects.

- Holding/tilting water until the cylinder contains exactly **100 mL** dispatches `LIQUID_TRANSFER_COMPLETED` for water → cylinder; moving the measured 100 mL to the beaker dispatches the next liquid completion event. Partial flow is stateful and never itself marks a transfer complete.
- Scooping salt into the spatula and depositing it in the boat each publish a distinct accepted `SOLID_TRANSFER_COMPLETED` receipt. Placing the 5 g-loaded boat on the simulated digital balance publishes `MASS_MEASUREMENT_RECORDED` only after the scene relationship confirms real contact. Tipping the boat into the beaker publishes `SOLID_TRANSFER_COMPLETED` for boat → beaker.
- Completing the required _genuine circular stirring gestures_ until the modelled 5 g dissolves emits `STIRRING_REQUIREMENT_COMPLETED`. The physical result (no undissolved modelled solid) permits a separate observation event; the animation timer **does not** mark the process complete.
- The final review is completed by **clicking the actual 3D beaker after the accepted observation**, which dispatches `REVIEW_INSPECTED`. No independent Next or Validate control can substitute for these physical steps in the active laboratory route. The legacy T08 pure workflow API is retained for backward-compatible internal tests but is no longer the live UI progression mechanism.

`tests/simulationEvents.test.mjs` covers the pure event engine: wrong units/quantities/targets, absent equipment, stale or fabricated chemistry, replayed and out-of-order events, partial stirring, full nine-step completion and fresh reset. Existing `tests/directInteractions.test.mjs` and `tests/workflowEngine.test.mjs` exercise the integrated domain event bridge. These tests do **not** replace hands-on mouse/WebGL QA or production deployment checks.

### Task E: Contextual educational guidance and unobtrusive hints

- `lib/contextualGuidance.ts` exports the **pure read-only** `getContextualGuidance` selector. It combines the current validated workflow step, actual beaker/cylinder volume, salt distribution, selected/hovered/dragged equipment, bench placement, semantic balance relationship, accepted events and current-step validation into one short instruction and optional contextual gesture hint. A student's chosen apparatus never implies a completed action; hints have no chemistry, workflow or movement side effects.
- The **primary step HUD** is compact and reacts to the quantities actually on the bench: measure the missing fraction of the 100 mL cylinder target, pour measured water into the beaker, scoop NaCl with the spatula, transfer it to the boat and simulated tared balance, tip the weighed boat into the beaker, stir in real circles, observe the state and inspect the finished beaker. Choosing **Hint** only shows instructions; it does not dispatch any scientific event. Selecting an instrument displays its applicable gesture automatically. The separate detailed guide remains optional, and its checklist and scientific reference are expandable.
- `three/affordanceHintLogic.ts` and `three/EquipmentAffordanceHints.tsx` choose **one** compatible, placed receiver using the expected actor/gesture, actual chemical quantities, validated step and the same world-space contact threshold as interaction gestures. A receiver shows a **teal halo when near**, **faint amber when far**, and **no green** if the tool/receiver or prerequisites are wrong. The visual ring stays visible **while equipment is being dragged or held**, uses raycast-inert geometry, and cannot change the physical or scientific state.
- Main HUD feedback distinguishes actionable current-step errors from accepted semantic events. A newly accepted event shows a brief confirmation that fades; simply displaying a hint or a pour stream cannot validate progress. The four essential live readings remain visible while extra measurement details are collapsed by default. Mouse help is a small nonmodal drawer, no longer a full-screen blocking overlay.
- `tests/contextualGuidance.test.mjs` covers the state selector, changing quantities, selected equipment, proximity, errors, successful partial sub-actions, full completion and restart. `tests/affordanceHints.test.mjs` checks compatibility, genuine contact distance, wrong actors and quantity-dependent targets. Both are included in `npm test` alongside the existing A–D regression suite.

### Task F: Mouse-first interaction discoverability and modular UI

The main control surface remains the **3D lab**, not a dashboard. The laboratory route stays `h-dvh` / no vertical page scrolling; the small inventory, contextual instruction, measurements and optional scientific guide are all overlays. Direct operations, deterministic chemistry, nine validated scientific stages, camera bounds, equipment footprints, mouse capture and the atomic `SimulationEvent` state machine are preserved from Tasks A–E.

**Discoverable mouse interactions:**

- Hover over a placed apparatus: its selection outline and short in-scene tool label identify it; generic body hover displays **grab**, hovering a TILT handle displays **vertical-resize**, and an active grab displays **grabbing**. **Left-drag the equipment body** to move it on the bench; the selected halo persists until deselection. **Left-drag an empty area** to orbit, **right-drag empty space** to pan, and scroll to zoom. Beginning a physical drag disables OrbitControls to prevent camera/object conflicts.
- Water container, graduated cylinder and weighing boat now have **visible teal `TILT` grips** beside their actual 3D models, with a generous invisible pick sphere and short `Left-drag ↓ to pour/tip` instructional labels. The **primary operation is left-dragging the grip downward** while aligned near the appropriate highlighted receiver. A held vessel pours incrementally from actual scientific state at the existing modelled upper rate of 45 mL/s. Release, straighten, cancellation, lost capture and leaving target proximity stop the stream. Old right-drag and Shift+left-drag tilt remain optional shortcuts, not prerequisites.
- A compatible receiver is indicated using world-space footprint/contact thresholds: teal when near, muted amber when far. Wrong targets, missing apparatus and invalid quantities cannot glow as valid. The spatula must physically scoop NaCl from its jar and release into the boat; the loaded boat is placed on the simulated digital balance and then tilted to the beaker. The stirring rod still requires physically meaningful **mouse circles** inside the beaker. The lab never uses an external Pour/Add Salt/Stir procedure button.
- Inventory click then workbench click remains an accessible **mouse-only alternative** to HTML drag-and-drop. The placement preview now shows a semi-transparent model, red/teal floor bands and a short in-world placement-validity explanation; the ghost never captures raycasts, and updates skip under-1-mm pointer jitter. Valid drops confirm in the science-independent placement store, invalid drops stay editable and cancel remains available. Existing equipment drag feedback also uses non-raycast location previews.
- `components/LaboratoryInteractionCoach.tsx` and pure `lib/mouseInteractionCoach.ts` provide a small first-use/mode-specific pointer legend, including selection, pouring, scooping, stirring, invalid placement and relevant corrective feedback. Main step hints prioritize the **left-mouse grip** and scientific context. `components/ContextualInstruction.tsx` and `state/useContextualGuidance.ts` isolate rapidly changing selected/hover/position subscriptions from the entire `LaboratoryLayout` shell; `lib/semanticFeedback.ts` centralizes labels for **accepted semantic events only**. ## Conventions

- Prefer the `@/` import alias for cross-directory imports. Keep feature-specific code in its feature folder, shared components in `components/`, and route composition in `app/`.
- Define core colors, typography, spacing, radii, shadows, and breakpoints in `src/styles/tokens.css` through Tailwind's `@theme`. Keep UI accessible and responsive.
- Route-level pages use `usePageTitle` to set meaningful document titles. Use semantic landmarks, labeled navigation, keyboard focus outlines, and reduced-motion support.
- The initial UI is English. `src/app/locale.ts` centralizes document `lang` and `dir` for eventual Arabic localization. Prefer logical CSS properties and direction-safe layout utilities. This is **not** a translation implementation.
- The three `mockExperiments` entries are clearly labeled illustrative examples, and no official academic semester, unit, lesson or experiment is implied.

## Prototype boundaries

This release includes **no authentication, backend, database, AI integration, validated dissolution kinetics, CFD, gravity-driven rigid-body dynamics, calibrated sensor-based weighing, approved curriculum data, or full localization**. T08 adds verified procedural progress to controlled T07 pouring, salt addition and simplified stirring; the direct-manipulation route now triggers those transitions through spatial gestures rather than chemistry buttons. It does not represent the creation of a new compound or a validated real-world laboratory measurement. The optional scientific reference reading position has no authority to advance experiment completion. The safety overview is generic orientation, not a replacement for instructor guidance or official risk assessments.

The 13.7-second vertical reference video present in the project root shows a third-party-style 3D educational simulation catalogue and movable-looking equipment (water vessel, sodium jar, beaker, tool inventory); it is preserved and not loaded by the application. It is inspiration/reference footage, **not a captured browser acceptance test of this React application**.
